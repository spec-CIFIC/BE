# 플랫폼 전략 — 앱/웹 분리 + 폰 "말문제" 특화

> 제품/아키텍처 방향 결정 문서. BE/FE 양쪽 `.claude/plans/`에 동일하게 유지한다.
> 근거 ADR: Notion "왜 Expo인가" §7 (2026-08-20 업데이트).

## 결정 (2026-08-20)

- **앱과 웹을 분리한다.** 앱은 기존 **Expo(React Native) 그대로**, **웹은 후속으로 Next.js(+shadcn/ui) 별도** 구축.
- **앱 먼저, 웹은 그 다음.** 앱 프레임워크 재설계 없음 — Expo는 원래 앱 주력이라 웹 분리 시 앱은 더 깔끔해진다.
- **폰(앱) = "말문제" 특화**, **웹(노트북) = 계산문제 등 본격 학습**.

## 왜 바꿨나

- 그동안 도메인을 **개발자 관점으로만** 판단("앱 우선, 웹은 덤")했다.
- **2026-08-20 잠재고객·파트너 면담**에서 반례 발견: 수험생 다수가 공부 시 폰을 **2G/피처폰으로 바꾸고 노트북으로만 공부**한다 → **웹 필수**.
- 폰으로 문제 푸는 사용자는 **소수** 예상 → 폰엔 계산문제 대신 이동·틈새시간용 **말문제**(계산기·연습장 불필요, 빠른 O/X)를 특화.

## 말문제 vs 계산문제 (도메인 정의)

- **말문제(이론문제)**: 계산 없이 개념·기준서·법조문의 옳고 그름을 판단. 짧은 O/X. 폰/틈새시간에 적합.
- **계산문제**: 숫자를 계산해 답 도출(감가상각·세액·원가). 계산기·집중 필요. 노트북/책상에 적합.

## 플랫폼 ↔ 문제 유형

| 플랫폼 | 맥락 | 문제 유형 |
|---|---|---|
| 앱(폰, Expo) | 이동·틈새시간 | 말문제 |
| 웹(노트북, Next.js) | 책상·집중 | 계산문제 중심 |

## 실행 방침

1. **지금**: 앱(Expo) 계속 개발. 프레임워크 재설계 안 함.
2. **웹 분리 시**: Next.js로 별도 구축. `lib/api`·`lib/store`·타입·`fe-integration.md`(BE 계약) 재사용. **BE 변경 없음**.
3. 앱에 남은 웹 대응 코드(`Platform.OS==='web'` 분기, 모바일 뷰포트 wrapper)는 무해하므로 유지, 웹 분리 확정 시 정리.

## 열린 과제

- **말문제 생성·검증 신뢰도**: CPA 채택 근거는 계산문제의 코드 채점 가능성(검증 파이프라인 2단계)이었다.
  말문제는 이 강점과 결이 달라(정답 판정은 되나 생성 검증이 계산만큼 결정론적이지 않음),
  말문제용 검증 전략은 별도 과제로 남긴다.
- 웹 분리 착수 시점(앱 완성도/사용자 요구 임계값) 기준 미정.
